# Сервис контроля качества данных (ККД) по целям

Бэкенд-сервис для контроля качества данных (ККД) по целям и ключевым результатам.
Стек технологий: **Java 21**, **Spring Boot 3**, **PostgreSQL**, **Liquibase**, **Docker**.

## Как запустить проект

1. Убедитесь, что у вас установлены Docker и Docker Compose.
2. Создайте файл `.env` в корне проекта (скопируйте из `.env.example`):

```bash
cp .env.example .env
```

3. Запустите базу данных PostgreSQL в фоне:

```bash
docker-compose up -d
```

4. Запустите Spring Boot приложение:

```bash
./mvnw spring-boot:run
```

Приложение будет доступно по адресу: `http://localhost:8080`.

## Как запустить тесты

Выполните команду в терминале:

```bash
./mvnw test
```

В проекте реализованы JUnit 5 тесты с использованием Mockito. Они покрывают граничные условия правил, расчет метрик и расчет дельты.

## Миграции базы данных (Liquibase)

Схема БД и стартовые данные управляются Liquibase (`src/main/resources/db/changelog/`).
Миграции применяются автоматически при старте приложения.

Чтобы проверить накат -> откат -> повторный накат вручную, используйте плагин Liquibase для Maven:

1. Накатить все миграции:

```bash
./mvnw liquibase:update
```

2. Откатить последний changeset:

```bash
./mvnw liquibase:rollback -Dliquibase.rollbackCount=1
```

3. Накатить снова (проверка идемпотентности):

```bash
./mvnw liquibase:update
```

## Архитектура решения

Проект следует слоистой архитектуре:

* **Слой API (`controller`)**: REST-эндпоинты (`/api/runs`, `/api/kkd/summary`, `/api/kkd/issues`). Отвечает за валидацию входных параметров и формирование HTTP-ответов.
* **Сервисный слой (`service`)**: Содержит бизнес-логику:
    * `KkdRunService`: запускает правила и сохраняет результаты в БД.
    * `MetricsService`: рассчитывает метрику `clean_goals_share` (доля корректных целей) с учетом иерархии подразделений (каскадирование).
    * `DeltaService`: сравнивает текущий и предыдущий прогоны, вычисляя новые (`new`), оставшиеся (`persisting`) и исправленные (`resolved`) проблемы.
    * `SummaryService`: агрегирует метрики, статистику по severity и дельту для API.
* **Движок правил (`rule`)**: Изолированная бизнес-логика проверки данных.
    * Интерфейс `KkdRule` и 4 реализации: `GoalNoOwnerRule`, `KrWeightsSumRule`, `CascadeNoParentRule`, `KrStaleProgressRule`.
    * `RuleEngine`: загружает данные один раз и прогоняет через них все правила.
* **Слой доступа к данным (`repository`, `entity`)**: Репозитории Spring Data JPA и сущности Hibernate.

## Формат ошибок API

Все ошибки возвращаются в едином формате:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Run not found: RUN-123"
  }
}
```

* **404 Not Found** — неизвестный прогон или подразделение.
* **422 Unprocessable Entity** — некорректные параметры (например, отрицательный `limit` или `offset`, либо неверный тип данных).
